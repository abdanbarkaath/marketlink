# MM-2 — Public copy and entry points

[MM-2](https://marketlinksetup.atlassian.net/browse/MM-2) · Source and product-guidance baseline `4c5de71` · [Audit guidance](../product/intent-and-audit-priorities.md)

Small-business buyers should be able to choose relevant marketing help, recognize real listings, and reach a provider directly. Independent marketers and agencies should know where to sign in and how their profile is presented.

**Evidence.** Status describes source evidence: **VERIFIED** means the code establishes the behavior, **PARTIAL** means the contract exists with a gap, **MISSING** means the entry point or metadata is absent in the inspected source, and **UNVERIFIED** means runtime behavior was outside this pass. Prior browser specs were inspected. Desktop/mobile rendering, keyboard behavior, live delivery, and outcomes are unverified for this audit. All value statements below are expected effects. P1 is reserved for verified misdirection. P2 covers testable friction or an optional improvement to a core task. P3 covers low-impact or speculative changes. Keep rows establish regression expectations.

## Recommended order

1. Ask the owner to choose the agency entry point. This is the only confirmed P1 issue.
2. Check whether buyers reach relevant live results, understand applied filters, and can return from a profile. Review the verified mismatch between the match selector and taxonomy-derived search before adding shortcuts. Approve service or goal shortcuts and search-return changes only if they serve those tasks.
3. Preserve the approved demo, guest contact, location privacy, and route aliases. Verify mobile and keyboard behavior before changing copy or layout.

## Journey checklist for the approved follow-on

1. **Homepage → directory.** Submit blank and valid ZIP/name searches. Confirm direct browse and the expected query parameters. Exercise sample checkbox, sample pin, and example dialog independently. If live entry links are approved, select a service and a buyer goal through their respective links and verify the destination and applied label.
2. **Directory → profile.** Open a shared filter URL in a fresh session. Exercise catalog search, an unmatched term, any/all, reset, sorting and pagination. Open a named active provider from a card. Verify the expected return behavior and compatibility aliases.
3. **Profile → contact or sign-in.** With an active development listing, use the contact jump, submit a test inquiry as a guest, and verify receipt in the provider dashboard. Try invalid and retry states. Separately follow the header sign-in entry and verify the correct role dashboard. An inactive listing must offer no live enquiry form.
4. **Keyboard and mobile.** Repeat with keyboard and at narrow widths. Check visible focus, modal dismiss/return, map alternative, filter labels, readable buttons and normal Back behavior. Reference existing [homepage specs](../../marketlink-frontend/tests/home-marketplace.spec.ts#L5), [directory specs](../../marketlink-frontend/tests/directory.spec.ts#L5), and [profile specs](../../marketlink-frontend/tests/agency-detail.spec.ts#L24). Run against fixtures for deterministic UI and development data for end-to-end delivery.

## Planned measurement, subject to separate approval

Observe a small set of U.S. small-business owners attempting the same tasks before and after an approved change. Include a known service and a plain-language business goal. Record the first destination, whether it has the intended query, wrong-category visits or backtracking, and whether the participant reaches a relevant profile and the correct contact action. Report counts with denominators and describe the fixture/data conditions. For providers, record whether an invited participant reaches the correct dashboard without creating a buyer account.

If measurement is later added to the product, count CTA clicks, successful directory arrivals, profile opens and confirmed inquiry submissions. Use route and taxonomy identifiers. Keep account credentials, ZIP, profile identifiers and inquiry text out of the measurement payload. A/B testing, participant studies, and any effect on completion rates are planned only. No outcome was measured in this audit.
