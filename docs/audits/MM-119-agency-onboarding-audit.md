## Findings that affect MM-120

1. **P1 · VERIFIED — Approximate agency location leaks precision through API output.** The editor offers approximate to every expert type and the public UI hides ZIP in the label. The sanitizer returns immediately unless the expert is both a creator and approximate. An approximate agency can therefore return street address, ZIP and raw coordinates. The detail map receives the API coordinates. Radius distance uses raw coordinates before sanitization, including for approximate creators. Align display, list/detail JSON and distance output with the promised precision, and decide how public approximate maps work before offering that option at setup. [Editor](../../marketlink-frontend/src/app/dashboard/profile/page.tsx#L725) · [Public label/map](../../marketlink-frontend/src/app/experts/%5Bslug%5D/page.tsx#L377) · [Sanitizer](../../marketlink-backend/src/routes/providers.ts#L138) · [Radius](../../marketlink-backend/src/routes/providers.ts#L672)
2. **P1 · VERIFIED — Service edits can remove tokens.** The picker derives choices from overlapping aliases and can leave ambiguous legacy selections unresolved. Unmatched tags have their own display, but committing help choices rebuilds the complete token array from those choices. It does not retain unmatched or ambiguous tokens automatically. The picker limits new selection to three areas and eight help types, while the database stores a flat token array. Keep explicit removal and verify broad legitimate agencies before changing limits. [Picker limits and derivation](../../marketlink-frontend/src/components/TaxonomyServicePicker.tsx#L33) · [Commit behavior](../../marketlink-frontend/src/components/TaxonomyServicePicker.tsx#L188) · [Taxonomy helpers](../../marketlink-frontend/src/lib/marketingTaxonomy.ts#L1348)
3. **P1 · VERIFIED — Critical selection and errors have accessibility gaps.** Location suggestions and both taxonomy suggestion lists commit using `onMouseDown`. No Arrow/Enter/Escape selection handling is implemented in these controls. Some visible labels have no programmatic input association, including business name and address. Form errors lack focus routing or a live announcement, and the create button is disabled until fields are filled. Exact address selection can clear unconfirmed text on blur, with no manual location path in the onboarding form. The source shows barriers, while the frequency of abandonment and actual assistive-technology behavior are unmeasured. [Onboarding form](../../marketlink-frontend/src/app/dashboard/onboarding/OnboardingForm.tsx#L93) · [Autocomplete](../../marketlink-frontend/src/components/LocationAutocompleteField.tsx#L141) · [Taxonomy suggestions](../../marketlink-frontend/src/components/TaxonomyServicePicker.tsx#L244) · [Editor save errors](../../marketlink-frontend/src/app/dashboard/profile/page.tsx#L406)
4. **P1 · MISSING — No private evidence staging or per-entry public consent.** Owner save replaces supplied project, client and media arrays transactionally. The editor submits all three arrays on every save. Public selects include every stored row for an active expert and feature flags control neither visibility nor consent. Existing support is sufficient to publish redacted work, but cannot privately store confidential work for later release. Consider omitting untouched arrays from profile PUT when implementing section saves so unrelated edits preserve IDs and content. [Editor serialization](../../marketlink-frontend/src/app/dashboard/profile/page.tsx#L458) · [Transaction](../../marketlink-backend/src/routes/providers.ts#L1427) · [Public selects](../../marketlink-backend/src/routes/providers.ts#L325)
5. **P2 · PARTIAL — Server validation and owner form requirements differ.** Address and ZIP are optional at the API boundary. Several expert create values are directly trimmed without runtime type guards. The PUT handler checks hourly bounds together when both are supplied, so other callers can submit inconsistent partial changes. Section saves should test the final persisted values and preserve blank/omitted/cleared distinctions. [Create handler](../../marketlink-backend/src/routes/providers.ts#L842) · [Update rates](../../marketlink-backend/src/routes/providers.ts#L1270) · [Owner save](../../marketlink-frontend/src/app/dashboard/profile/page.tsx#L406)
6. **P2 · PARTIAL — Progressive completion starts after creation, with no dedicated resume view.** Onboarding already leaves proof and pricing to the editor. It routes to the public page after create and the editor routes back to the dashboard after save. The editor stores unsaved form state in the browser component. Existing persisted values can be loaded again, but no private draft or section completion status was found. A save/resume contract should mean reloading successfully saved values. Pre-create drafts or unsaved recovery require a separate decision. ## Proposed MM-120 implementation scope

1. **PROPOSED · Essentials.** Keep the existing name, expert type, city/state and at least one genuine service. Reuse location autocomplete, allow a city/state path when precise address is unnecessary or unavailable, and align public location output with the selected precision before promising privacy. Explain the listing’s current publication behavior at the create action. Decide whether the contact email projection must be addressed before release.
2. **PROPOSED · Services and fit.** Reuse the two-stage taxonomy picker, configured service aliases and `Expert.services`. Preserve pre-existing tokens during adds and unrelated saves, and make removal explicit. Reuse the existing description, specialties, industries, client sizes and coverage fields to describe buyer fit. Keep discovery `any/all` behavior and existing deep links.
3. **PROPOSED · Save and resume.** In the current editor, group optional work into services/fit, coverage, pricing and public evidence. Link from setup to the editor or its existing sections and provide a public profile link with the status of the saved listing. Derive progress from existing data and separate essential setup from optional details. Do not treat missing client names, project results or pricing as failures. Persist successfully saved sections to the existing record, keep unrelated fields intact, and show actionable errors before navigating away.
4. **PROPOSED · Evidence and preview.** Reuse projects for anonymous public case studies and clients only for authorized attribution. Provide field-level public visibility guidance and a confirmation before publishing identifiable third-party details. Existing active profile output can preview saved public content after a successful save. If a preview of unsaved/private data is approved, keep it owner-only and verify it independently from the public route. Defer draft/private records, per-item publication or consent history unless review establishes a need for durable storage.
5. **PROPOSED · Accessibility and presentation.** Associate labels and field help, reuse a keyboard-operable combobox pattern with Arrow keys, Enter and Escape, and expose selection/removal names and status. Focus a linked error summary or first invalid field on submit. Preserve the user’s inputs on recoverable errors. Keep the existing design direction, readable density and visible focus. Check mobile wrapping, target sizes, contrast and zoom in actual renders. [Design contract](../../DESIGN.md)

### Acceptance and regression checklist

- **P1** Create a minimal agency through the authorized provider flow with no clients, projects or prices. Resume editing after sign-out/in and confirm successfully saved values persist. Verify customer/admin guards and unrelated provider types still work.

- **P1** Save an approved redacted project without a client, results or media. Verify active profile output has no accidental names/logos/links or inferred verification. Add/remove an authorized named entry and verify unrelated rows survive ordinary saves.
- **P1** Seed an existing token mix in isolated test data, add and remove chosen services, save, reload and verify exact retained tokens plus legacy direct search and grouped any/all discovery. Test overlapping aliases, several disciplines and unmatched tags.
- **P1** Complete onboarding and edit by keyboard and assistive technology. Verify labels, combobox semantics, visible focus, Escape, error announcements, mobile interactions and behavior when location lookup fails. Review desktop/mobile screenshots, including an optional section and an error state.
- **P2** Cover malformed payloads, nullable pricing including quote-only display, save failures and omitted versus explicitly cleared collections. Run scoped backend tests and frontend lint/build plus Playwright on the implementation PR. Record which checks use mocked API responses and which exercise the real local application.
