## Implemented contracts and consumers

### Provider discovery

| Endpoint | Current contract |
| --- | --- |
| `GET /experts`, `GET /providers` | Public, active experts only. Returns `{meta:{total,page,limit,totalPages,sort,order},data:[…]}`. Rows include identity, type, description, location, trust, services, creator fields, pricing and creation date. Radius results add `distanceMiles`. Source `marketlink-backend/src/routes/providers.ts:260–282,452–729`. |
| `GET /experts/:slug`, `GET /providers/:slug` | Returns a bare detail object with profile, contact/location, pricing, projects, clients, media, reviews, certifications and awards. Active rows are public. Pending/disabled rows require an authenticated owner. Absent rows and non-owner access to inactive rows return `404 {error}`. Approximate creator list/detail responses hide ZIP, hide street address when selected, and round returned coordinates to one decimal. Source `marketlink-backend/src/routes/providers.ts:138–173,284–348,732–764`. |
| `GET /location/autocomplete?q=&type=`, `GET /location/zip/:zip` | Public. Autocomplete accepts `city/state/postcode/address` and returns `{ok:true,suggestions}`. Empty query returns an empty list. ZIP lookup returns geocode and normalized location fields on success. Lookup failures return `400` or `503` when geocoding is unconfigured. Source `marketlink-backend/src/routes/providers.ts:410–450` and `marketlink-backend/src/lib/geocoding.ts:14–58,172–225,275–342`. |
| `POST /experts` and `POST /providers` | Signed session. Requires business name, city, state, expert type and services. Uses account email, generates slug, and can geocode the location. Returns `201 {ok:true,expert,provider}` with the same record under both keys. Existing profile or unique conflict returns `409`. Source `marketlink-backend/src/routes/providers.ts:767–1007`. |
| `PUT /experts` and `PUT /providers` | Signed session and owned expert. Updates supplied profile fields. Supplied project/client/media collections replace those collections in a transaction. Returns `{ok:true,expert,provider}`. Source `marketlink-backend/src/routes/providers.ts:1013–1473`. |

List query parameters are `name` (business name substring), `q` (name/tagline/short-description substring or exact normalized service token, max 200 characters), `city` (prefix), `expertType` (`agency/freelancer/creator/specialist`), `service` (comma-separated tokens), `serviceGroups` (JSON array of token arrays, max 12,000 characters, up to 64 groups and 50 tokens per group), `match` (`any` by default or `all`), `minRating` (unsigned decimal string), `verified` (`true/1/false/0`), `zip` and `radius` (five-digit U.S. ZIP and one of `5/10/20/50/100` together), `sort` (`newest/name/rating/verified/distance`), `order` (`asc/desc`), `page` (default 1) and `limit` (default 20, clamped to 1–50). Name and distance default to ascending, other sorts to descending. Distance requires ZIP and radius. Grouped `all` requires a match in every group, with synonyms treated as alternatives within a group. If both service filters are sent, both apply. Radius matching excludes rows without coordinates. Empty results still return at least one total page. Source `marketlink-backend/src/routes/providers.ts:14–33,260–282,489–727` and `marketlink-backend/src/lib/providerSearch.ts:3–22`.

- `marketlink-frontend/src/app/providers/page.tsx` redirects to `/experts` while forwarding query parameters. `marketlink-frontend/src/app/providers/[slug]/page.tsx` redirects to `/experts/:slug`.
- `marketlink-frontend/src/app/experts/page.tsx:9–38` makes a server-side uncached `GET /experts` without a cookie. It maps selected skill IDs to `serviceGroups` and taxonomy selections to `service`, then hands `data/meta` to `ExpertsDirectory`. The backend supports `city` but this page omits it from its URL-to-API allowlist. The page maps all backend `400` responses to one search message.
- `marketlink-frontend/src/app/experts/[slug]/page.tsx:317–342,690–694` fetches detail in the browser, handles `404` separately and shows the inquiry form for active records. The fetch omits explicit credentials, so cross-origin requests do not carry the session needed for inactive owner detail. `marketlink-frontend/src/components/LocationAutocompleteField.tsx:104` consumes autocomplete. No frontend call to ZIP lookup was found in `marketlink-frontend/src`.
- `marketlink-frontend/src/app/dashboard/onboarding/OnboardingForm.tsx:56` and `marketlink-frontend/src/app/dashboard/profile/page.tsx:492` send credentialed JSON to the create and update routes.

### Authentication and accounts

| Endpoint | Current contract and status |
| --- | --- |
| `POST /auth/signup` | `{name,email,password}`. Trims name, trims/lowercases email and requires password length of at least 8 characters. Creates a customer and customer profile, then creates a session. `201 {ok:true,user:{id,email,role,mustChangePassword},expiresAt}` plus signed cookie. `400` for current field checks, `409` if the initial email lookup finds a user. `marketlink-backend/src/routes/auth.ts:7–62`. |
| `POST /auth/login` | `{email,password}`. `200` with the signup success shape and signed cookie. `400` for missing fields, `401` for invalid credentials, `403` for a disabled user with a password hash. `marketlink-backend/src/routes/auth.ts:69–120`. |
| `GET /auth/me`, `GET /me` | Signed session or `401 {error}`. Both return `{ok:true,user}`. `/me` returns `id/email/role`. `/auth/me` additionally returns `mustChangePassword/isDisabled`. `marketlink-backend/src/routes/auth.ts:126–141` and `marketlink-backend/src/routes/account.ts:8–12`. |
| `POST /auth/logout` | Attempts to delete the current session, clears the cookie and returns `{ok:true}`, including when there is no session. `marketlink-backend/src/routes/auth.ts:147–150` and `marketlink-backend/src/lib/session.ts:116–122`. |
| `POST /auth/change-password` | Signed session and `{currentPassword,newPassword}`. Requires the current password and at least eight characters for the replacement. Updates the hash and clears `mustChangePassword`. Returns `{ok:true}` or `400/401/403`. `marketlink-backend/src/routes/auth.ts:157–200`. |
| `GET /me/summary` | Signed session or `401`. Customer gets `customer:{id,name,businessName}` or null, `customerStats:{activeRequestCount,pendingProposalCount,conversationCount}` and null expert aliases. Other roles get null customer fields and an owned expert or null under both `expert` and `provider`. `marketlink-backend/src/routes/account.ts:15–159`. |
| `GET /me/provider-stats` | Signed session, provider role and owned expert, with `401/403/404` respectively. `{ok:true,stats}` includes total/new inquiries, conversation count, matched request count, needs-proposal count and pending/accepted proposals for the matched request set. `marketlink-backend/src/routes/account.ts:161–236`. |
| `PUT /me/customer-profile` | Signed session and customer role. `{name,businessName?}` upserts by user ID and returns `{ok:true,customer:{id,name,businessName}}`. Omitting or blanking business name clears it. `400` for missing name, `401` without session, `403` for other roles. `marketlink-backend/src/routes/account.ts:238–274`. |

Session tokens are random and stored in PostgreSQL. `expiresAt` in auth responses is epoch **milliseconds**. The signed `session` cookie is HttpOnly and path `/`. Production uses Secure and SameSite=None, development uses SameSite=Lax. TTL defaults to seven days. The server accepts credentialed CORS from the configured `WEB_URL` and local development origins. Source `marketlink-backend/src/lib/session.ts:21–28,49–113` and `marketlink-backend/src/server.ts:16–65`.

- `marketlink-frontend/src/app/login/page.tsx:68–80,117–145` and `marketlink-frontend/src/app/signup/page.tsx:69–81,127–155` send credentialed JSON, then use `/me/summary` for role-based routing. `marketlink-frontend/src/components/AppHeader.tsx:33–65` uses the same summary for navigation. No frontend call to `/auth/me` was found in `marketlink-frontend/src`.
- `marketlink-frontend/src/components/LogoutButton.tsx:17` calls logout. `marketlink-frontend/src/app/dashboard/profile/page.tsx:546` calls change-password. `marketlink-frontend/src/app/dashboard/page.tsx:81,122` consumes summary and provider stats. `marketlink-frontend/src/app/dashboard/customer/CustomerProfileForm.tsx:46` writes customer profile.
- `marketlink-frontend/src/lib/serverApi.ts:5–44` forwards the incoming Next.js cookie header for server-side calls, uses `no-store`, and parses `error` or `message`. Server-side consumers include `marketlink-frontend/src/app/dashboard/onboarding/page.tsx:14–39` and `marketlink-frontend/src/app/dashboard/customer/page.tsx:64–76`. Successful forwarding depends on the browser sending the cookie to the Next.js host.

### Inquiries

| Endpoint | Current contract and consumer |
| --- | --- |
| `POST /inquiries` | Public JSON `{expertSlug, name, email, phone?, message}`, with `providerSlug` accepted as an alias. Trims values, lowercases email, applies an email pattern, and caps name/email/phone/message at 100/200/40/2,000 characters. Only active experts can receive submissions. `201 {ok:true,inquiry:{id,createdAt}}`, `400` invalid data, `404` missing/inactive expert, `500` caught write failure. Prisma defaults status to `NEW`. The handler writes a database record. Source `marketlink-backend/src/routes/inquiries.ts:6–68` and `marketlink-backend/prisma/schema.prisma:296–312`. Consumer `marketlink-frontend/src/app/providers/[slug]/InquiryForm.tsx:16–68` accepts any 2xx as success and renders `error/message` on failure. |
| `GET /inquiries` | Signed session and owned expert. `{ok:true,data:[{id,name,email,phone,message,status,createdAt}]}`, newest 100, `401` without a session and `404` without an expert. Source `marketlink-backend/src/routes/inquiries.ts:74–101`. |
| `PATCH /inquiries/:id` | Signed session and ownership check by `id + expertId`. Accepts `{status}` normalized to `NEW/READ/ARCHIVED`. `{ok:true,inquiry:{id,status,createdAt}}`, `400` invalid status, `401` unauthenticated, `404` missing or foreign inquiry. Source `marketlink-backend/src/routes/inquiries.ts:107–145`. `marketlink-frontend/src/app/dashboard/inquiries/page.tsx:38–107` filters the list in memory and updates status optimistically. |

## Verified findings and recommended fixes

Priority reflects impact and order of remediation. P1 is authorization, security or abuse exposure. P2 is contract correctness and reliability. P3 is lower-impact cleanup.

| ID | Priority | Evidence and impact | Recommended fix and verification |
| --- | --- | --- | --- |
| 1 | P1 | **Expert creation bypasses the provider role.** The frontend redirects customers and admins out of provider onboarding. Both POST aliases check only session and existing ownership. The create payload omits status, and Prisma defaults it to `active`, which is publicly discoverable. Ownership-only PUT and inquiry routes also accept a user of another role if that user owns an expert. `marketlink-frontend/src/app/dashboard/onboarding/page.tsx:14–39`, `marketlink-backend/src/routes/providers.ts:621–622,767–775,954–981,1013–1019`, `marketlink-backend/prisma/schema.prisma:84–95`, `marketlink-backend/src/routes/inquiries.ts:74–83,107–135`. | Enforce the intended provider-role policy on expert self-service and inbox routes, with an explicit decision for any existing cross-role ownership. Preserve both aliases and admin routes. Test authenticated customer, admin and provider cases on both write aliases, and verify a rejected create cannot appear in discovery. |
| 2 | P1 | **Session authorization and revocation are incomplete.** The shared helper returns disabled users with an otherwise valid session. Password change updates the hash without revoking other sessions. `mustChangePassword` is set by admin credential flows and returned by auth, but the audited protected handlers do not enforce it. Logout suppresses session deletion failures before returning success. `marketlink-backend/src/lib/session.ts:89–126`, `marketlink-backend/src/routes/auth.ts:98–119,147–199`, `marketlink-backend/src/routes/admin.ts:239–310`. | Reject disabled users in the shared session authorization path. Define when a forced password change blocks protected actions, keeping change-password/logout reachable. Revoke sessions on password reset/change according to that policy and distinguish a missing session from a failed revocation. Test signed, tampered, expired, disabled and revoked cookies and forced-change behavior. |
| 3 | P1 | **Sensitive or costly routes lack application-level throttling.** Rate limit is registered with `global:false`. Auth, inquiry intake, autocomplete and radius search have no per-route limit. Login returns `403` for a disabled account before checking its password, revealing disabled-account state to an unauthenticated caller. `marketlink-backend/src/server.ts:48–54`, `marketlink-backend/src/routes/auth.ts:7–24,69–105`, `marketlink-backend/src/routes/inquiries.ts:13–63`, `marketlink-backend/src/routes/providers.ts:411–449,611–619`. | Use the existing rate-limit plugin on public write and expensive lookup routes. Check the password before revealing disabled status or return a uniform credential error. Verify thresholds, `429` handling and proxy IP configuration before rollout. Existing edge limits and observed abuse are unverified. |
| 4 | P1 | **Public location and contact output needs a field-level review.** Detail exposes expert email, phone and `disabledReason` in its public select. Self-service creation copies account email into expert email. Approximate creators still get `distanceMiles` computed from raw coordinates to one decimal across arbitrary accepted ZIP centers. The response rounds coordinates only after calculating distance. `marketlink-backend/src/routes/providers.ts:138–173,284–348,672–727,954–971`. | Confirm which contact fields are intentionally public. Exclude internal fields from the public projection and use privacy-appropriate coordinates or coarser distance output for approximate creators. Test list/detail output for creator, agency and owner cases. Location inference from repeated ZIP queries is a risk inferred from the calculation. No real profile was tested. |
| 5 | P2 | **Several write handlers rely on TypeScript assertions and coercion.** Signup accepts a nonempty malformed email and has a duplicate-email lookup/create race. Auth, customer profile and inquiry handlers stringify malformed input. Expert creation calls `.trim()` directly on several body values, so a truthy non-string can produce `500`. Create declares fields such as `websiteUrl` and `projects` but never persists them. Partial hourly-rate updates check the ordering only when both bounds are supplied. Profile and nested URLs are trimmed without protocol validation and some are passed to public link attributes. `marketlink-backend/src/routes/auth.ts:7–61,161–174`, `marketlink-backend/src/routes/account.ts:238–269`, `marketlink-backend/src/routes/inquiries.ts:13–40`, `marketlink-backend/src/routes/providers.ts:776–859,954–981,1209–1227,1270–1304,1360–1419`, `marketlink-frontend/src/app/experts/[slug]/page.tsx:381–454,532–534`. | Add focused runtime schemas or explicit guards that preserve intended string/array aliases. Check email shape and bounds, catch unique-email conflicts as `409` and define a recoverable outcome if signup creates a user but session creation fails. Align accepted create fields with actual persistence. Validate final stored rate range and supported URL schemes. Test wrong types, boundary lengths, concurrent duplicate signup and partial writes. |
| 6 | P2 | **Search silently drops or ignores some input and does unbounded work on radius queries.** The UI drops `city` even from redirected legacy URLs. Unrecognized `verified` is ignored and `page` has a minimum but no maximum or safe-integer bound. Radius search loads all matching coordinate-bearing records before filtering, sorting and slicing. It rounds distance before comparing to radius. Neither sort path specifies a unique final tie-break. Geocoder failure for radius search becomes a generic `400`. `marketlink-frontend/src/app/providers/page.tsx:8–25`, `marketlink-frontend/src/app/experts/page.tsx:12–36`, `marketlink-backend/src/routes/providers.ts:24–33,594–619,624–636,672–715`. | Preserve the existing `city` filter for legacy links if supported. Validate filter and pagination bounds, add a deterministic final tie-break and test radius boundaries. Measure candidate volume before optimizing and use a database bounding-box prefilter if needed. Distinguish lookup outages from invalid input. Production latency and dataset size are unverified. |
| 7 | P2 | **Inactive owner preview depends on origin.** Backend detail allows a signed owner, but the browser fetch does not opt into credentials for a cross-origin API. Separately, server-side forwarding can only forward cookies received by Next.js, while the backend sets a host-only cookie. `marketlink-backend/src/routes/providers.ts:732–764`, `marketlink-backend/src/lib/session.ts:52–61`, `marketlink-frontend/src/app/experts/[slug]/page.tsx:317–334`, `marketlink-frontend/src/lib/serverApi.ts:7–16`. | Verify the deployed frontend/API topology with a browser, including sign-in, reload, SSR dashboard and inactive preview. If preview is intended and the origins differ, include credentials on that request. Verify a non-owner still receives `404`. If the cookie never reaches Next.js, address delivery in the existing deployment topology. |
| 8 | P2 | **Inquiry totals and write recovery can diverge.** Inbox filters/counts only the latest 100, while provider stats count all stored inquiries. No paging or truncation metadata is returned. An unsuccessful HTTP response reloads rows, but a network exception leaves the optimistic status displayed. The PATCH comment omits accepted status `NEW`. `marketlink-backend/src/routes/inquiries.ts:85–105,114–144`, `marketlink-backend/src/routes/account.ts:184–195`, `marketlink-frontend/src/app/dashboard/inquiries/page.tsx:38–107`. | Roll back or reload after a network failure. If inbox history is needed, preserve `data` and add paging metadata or show that the list is limited. Align the status documentation with the existing accepted values. Test foreign IDs, invalid status, transport failure and inboxes over 100 records. |
| 9 | P2 | **Production cookie policy depends on deployment configuration.** The server falls back to a known signing secret, permits localhost origins by default, and accepts requests without Origin in the CORS callback. Production sets SameSite=None. The audited session mutations have no explicit Origin/CSRF guard. `marketlink-backend/src/server.ts:20–53`, `marketlink-backend/src/lib/session.ts:52–65`, `marketlink-backend/src/routes/auth.ts:147–149`. | Require a configured production secret, review production allowed origins and test cookie-authenticated mutations across trusted and untrusted origins. Add an Origin or CSRF check where the deployed flow needs one, including bodyless logout. Secret configuration, browser behavior and exploitability are unverified. |
| 10 | P3 | **Response types and identity usage have drifted.** Login and signup type `expiresAt` as a string while the backend returns a number. `AppHeader` only reads role but calls summary, which includes profile data and customer count queries. Error envelopes vary across routes and Fastify validation. `marketlink-frontend/src/app/login/page.tsx:14`, `marketlink-frontend/src/app/signup/page.tsx:14`, `marketlink-frontend/src/components/AppHeader.tsx:33–65`, `marketlink-backend/src/lib/session.ts:71–77`, `marketlink-backend/src/routes/account.ts:8–61`. | Correct the response type, use the existing identity endpoint for role-only consumers where behavior matches, and preserve `error/message` compatibility while standardizing touched handlers. Test anonymous navigation and role-specific links. |
